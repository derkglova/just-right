# Just Right: project context for Claude Code

## What this is
A hackathon MVP (SDC Hackathon 2026, Domain 2: Orbyte Smart SME Challenge) by team Beginathon.
Just Right tells a small café or bakery manager **how many of each item to bake tomorrow**, so they throw away less and sell out less.
Deadline: **Sun 25 Oct 2026, 7:59 AM MYT**. Keep everything small and demo-able.

## The daily loop
1. **Closing count (staff, Telegram):** leftovers per item. If an item sold out, a rough time bucket: before 12 / 12–2 / 2–4 / after 4.
2. **Planner (code):** estimates demand from history and picks tomorrow's quantity.
3. **2 PM plan (manager, Telegram):** one message with a number and a reason per item, plus **Approve** and **Edit** buttons.
4. **Approve/Edit (manager only):** staff are blocked. Edit asks for a new number and a reason.
5. **Log + dashboard (web, manager only):** activity log (who, what, when), plan status, waste in RM per week, item prices and costs.
6. **Baker (Telegram):** receives the approved bake list.

## Planner logic (src/planner.py, already written)
- Demand = sold, plus an uplift when the item sold out (censored demand), based on how early it sold out.
- Newsvendor target = (price − cost) / price. Quantity = mean + z·sd (z from the target), using the last 28 days.
- Cap the change at ±15% of the usual batch per day. Always return a plain-language reason.
- Goal is the *right* amount of waste, not zero.

## Architecture (one Python process, deployed on Replit)
- `src/main.py`: starts the Flask dashboard and the Telegram bot (polling in a thread) and schedules the 2 PM plan.
- `src/planner.py`: pure functions, no I/O besides reading data files. Covered by tests.
- `src/bot.py`: pyTelegramBotAPI. Commands: `/start`, `/plan` (send the plan now, for demos), `/count` (closing count). Inline buttons for Approve/Edit and sell-out buckets.
- `src/db.py`: SQLite, tables `plans`, `daily_sales`, `activity_log`.
- `src/templates/dashboard.html`: one page, Chart.js from a CDN for charts.
- `src/data/*.json`: **simulated Orbyte data** (items, staff roles, sales history). Generated by `scripts/generate_data.py`.

## Rules
- **Never commit secrets.** Tokens and IDs come from env vars (`.env` locally, Replit Secrets in deployment). See `.env.example`.
- Roles come from env/staff config: only `MANAGER_TELEGRAM_ID` can approve or edit.
- All data is **synthetic**. Label it as such in the UI ("sample data", "estimated").
- Orbyte is **simulated**, not integrated (the committee confirmed this doesn't affect marks). Use Orbyte-like wording: "Approvals", "Activity log".
- Keep it simple: no auth system, no payments, no real POS.
- Small, frequent git commits with clear messages (judges review the commit history).
- The team must be able to explain every part, so prefer simple, readable code over clever code.
- Timezone: Asia/Kuala_Lumpur.

## Commands
```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python scripts/generate_data.py      # regenerate synthetic data
python src/planner.py                # print tomorrow's plan in the terminal
python -m unittest discover tests    # run tests
python src/main.py                   # run bot + dashboard
```
